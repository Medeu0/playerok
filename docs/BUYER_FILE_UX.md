# UX открытия single-file HTML покупателем

Как ожидается, что покупатель будет открывать `dist/<sku>.html` после
получения его в чате Playerok — и что из этого пока **не проверено на
реальных устройствах**. Ничего из этого документа не подтверждено кодом,
это ожидания на основе общего поведения браузеров, которые нужно
верифицировать вручную дома на реальных телефонах перед массовой продажей.

## Desktop

Покупатель скачивает `.html`-файл и открывает его в Chrome/Edge/Firefox
двойным щелчком или через "Открыть с помощью → браузер". Ожидается, что
работает без сюрпризов: `file://` в десктопных браузерах — стандартный,
многократно обкатанный сценарий. **Всё равно стоит проверить** хотя бы раз
вручную (уже сделано headless-Chromium'ом в рамках этой задачи, см. финальный
отчёт — но headless ≠ то, что реально увидит покупатель в своём браузере с
его настройками/расширениями).

## Android

Скачанный файл обычно открывается через приложение "Файлы" → выбор браузера,
или напрямую из уведомления загрузки. В большинстве случаев Chrome на
Android корректно открывает локальный HTML. **Требует проверки**:
- поведение при открытии прямо из уведомления загрузки Chrome;
- поведение, если у покупателя браузер по умолчанию — не Chrome (Samsung
  Internet, Firefox, Yandex Browser и т.п.);
- поведение localStorage в приватных/облегчённых режимах некоторых
  Android-браузеров.

## iPhone / iOS

Это точка наибольшего риска и наименьшей уверенности. Safari на iOS
исторически накладывает более строгие ограничения на локальные файлы и на
то, как вообще происходит "открытие" файла, полученного через мессенджер —
файл может открываться в предпросмотре (Quick Look) без полноценного запуска
JS/localStorage, а не в самом Safari. **Ничего здесь не подтверждено и не
должно восприниматься как обещание** — это именно то, что нужно проверить
руками на iPhone до того, как полагаться на этот канал доставки для
iOS-аудитории.

## Открытие вложения из чата Playerok

Как именно Playerok (веб/приложение) отдаёт HTML-вложение при скачивании —
через системный загрузчик, через собственный вьюер, с каким MIME-type — не
исследовано в рамках этой задачи (нет доступа к реальному Playerok-боту и
интерфейсу в этой среде). **Требует ручной проверки**: отправить себе тестовый
`dist/army-ss.html` через тот же канал, которым бот будет отправлять его
покупателям, и открыть на Android и iPhone.

## Итог: что обязательно проверить перед стартом продаж

- [ ] Android: скачивание из чата Playerok → открытие → работоспособность
      quiz/checklist/localStorage.
- [ ] iPhone/iOS: тот же сценарий; отдельно проверить, не открывается ли файл
      только в Quick Look без исполнения JS.
- [ ] Поведение при повторном открытии файла (localStorage должен сохранить
      прогресс между сессиями на том же устройстве/браузере).
- [ ] Если UX на мобильных окажется плохим (например, iOS открывает файл в
      режиме, где JS не выполняется) — рассматривать fallback на простой
      хостинг (просто раздать тот же файл по ссылке через статический
      хостинг), не меняя саму архитектуру сборки: `dist/<sku>.html` одинаково
      годится и для прямой отправки, и для выкладывания на статический
      URL, если понадобится.

Ничего из этого не является багом текущей реализации — это открытые вопросы
реального мира, которые код сам по себе не может закрыть.
